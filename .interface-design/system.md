# 市场研究台界面设计系统

本文件是项目所有页面和组件的 UI 基准。新增功能、重构和视觉修复都必须优先复用这里定义的规则以及现有组件；如确需偏离，应在代码审查中说明原因，并同步更新本文件。

## 1. 产品意图

- 使用者：每天快速检查全球市场、验证投资线索并继续深入研究的个人投资者。
- 核心任务：先在十几秒内获得“发生了什么、为什么、未来方向如何”，再按需展开数据、模型和来源。
- 体验关键词：冷静、可信、信息密集但不拥挤、接近研究终端而不是营销网站。
- 页面焦点：每个页面只能有一个首要任务。首页突出市场方向，驾驶舱突出传导链，量化页突出机会排序与执行闸门，市场页突出榜单和筛选，情报页突出最新内容。
- 产品签名：“市场传导脉冲”。用连续线段、方向状态和时间周期表达跨资产影响，不用装饰性渐变或无意义图形。

## 2. 设计原则

1. 结论先于证据：首屏展示摘要、方向和状态；长文本、回测、方法论与来源通过 `details` 渐进披露。
2. 数据必须可核对：更新时间、来源、状态和免责声明应可见，但视觉层级低于核心结论。
3. 颜色只表达含义：强调、上涨、下跌、警告和错误使用语义色；禁止为了装饰引入额外强调色。
4. 空间和字重建立层级：优先使用留白、字重和表面色差，避免依赖粗边框、大阴影或超大标题。
5. 保持原生语义：按钮使用 `button`，导航使用 `a`/`RouterLink`，展开区域使用 `details/summary`，表格数据使用 `table`。
6. 不伪造精度：预测、代理指标和降级数据必须明确标记，不用视觉效果弱化不确定性。

## 3. 色彩与主题

颜色必须引用 `src/assets/main.css` 中的语义变量，组件内禁止新增无语义的硬编码颜色。

### 基础变量

- 页面背景：`--paper`
- 标准卡片：`--surface`
- 控件与弱分组：`--surface-soft`
- 悬停与次级抬升：`--surface-elevated`
- 主文字：`--ink`
- 次级文字：`--muted`
- 分隔边界：`--border`
- 品牌与焦点：`--accent` / `--accent-soft`
- 危险与错误：`--danger` / `--danger-soft`
- 语义方向：`--positive`、`--negative`
- 警告与数据降级：`--warning` / `--warning-soft`

### 使用规则

- 页面中性结构约占 60%，次级表面约占 30%，语义色不超过约 10%。
- Light/Dark 必须使用同一套语义，不允许仅为某一主题硬编码 `white`、`black` 或灰阶。
- 深色主题主要依靠边界和细微表面明度区分层级；不要依靠大面积阴影。
- 上涨/下跌遵循当前中国市场习惯：上涨使用暖红语义，下跌使用绿色语义。
- 所有文字和交互状态必须在两种主题下保持清晰对比。

## 4. 深度与边界

采用“低对比边界 + 轻微表面变化”的技术型深度策略。

- 页面区块：通常不使用阴影，以留白或 `1px solid var(--border)` 分隔。
- 标准卡片：`1px` 边界，`10px` 圆角，不默认使用强阴影。
- 重点摘要卡：允许使用全局 `--shadow`，但一个视图不应出现多个竞争焦点。
- 控件：`6–8px` 圆角；卡片：`9–12px`；弹窗：约 `12px`。
- 嵌套圆角遵循同心规则：外层圆角应大于内层圆角与其间距的视觉总和。
- 禁止混用厚边框、强阴影、玻璃拟态和高饱和渐变。

## 5. 排版

### 字体

- UI、正文和控件：系统无衬线字体栈，沿用 `main.css`。
- 页面主标题、关键市场名称：`Georgia, 'Songti SC', serif`。
- 数据：必须启用 `font-variant-numeric: tabular-nums`。

### 字级

- 页面主标题：桌面 `36–54px`，移动端约 `32–40px`，字重 `500`。
- 区块标题：`24–28px`。
- 卡片标题：`14–18px`。
- 正文：`11–14px`，长文本行高 `1.6–1.75`。
- 标签与元数据：`9–11px`；重要内容不得小于 `10px`。
- 关键数据：`20–28px`，使用字重和语义色表达优先级。

### 文本行为

- 标题使用 `text-wrap: balance`；正文使用 `text-wrap: pretty`。
- 大标题使用轻微负字距，正文禁止过度字距。
- 长列表优先截断、分页或展开，不通过缩小字号塞入固定高度。
- 英文眉题使用大写和适度字距，但不得成为页面主视觉。

## 6. 间距与密度

使用 4px 基础网格，只使用 4 的倍数或经过验证的相邻值。

- 微间距：`4–8px`，用于图标、标签和紧密关联项。
- 控件内部：`8–16px`。
- 卡片内部：`14–20px`。
- 区块间距：`24–32px`。
- 大区块间距：`40–64px`。
- 页面桌面内边距：顶部约 `40px`，左右 `clamp(20px, 3.5vw, 52px)`。
- 页面移动端内边距：顶部 `24px`，左右 `14px`，底部约 `60px`。

同类内容紧密排列，不同任务之间留出明显呼吸空间。禁止所有卡片使用完全相同的尺寸和间距形成“停车场式”布局。

## 7. 页面架构

### 应用框架

- 桌面端保留 `248px` 左侧导航，内容在右侧工作区。
- 顶部栏固定展示当前页面名称、简短说明，并把任务状态、语言、主题和用户操作收拢为单一右侧操作区；`560px` 以下语言使用“中 / EN”短标签，主题仅保留图标，避免工具互相挤压。
- `900px` 以下侧栏变为抽屉，不占据内容宽度，并提供遮罩与关闭按钮。
- 页面内容宽度根据数据密度控制在约 `1200–1380px`，居中展示。

### 页面首屏

页面首屏依次包含：

1. 小型领域眉题。
2. 明确的页面主标题和一句用途说明。
3. 更新时间或数据状态。
4. 当前页面唯一的焦点区域。

首页焦点是“基准市场脉冲”；驾驶舱焦点是“市场传导链”；A股和美股焦点是热门榜单；情报中心在同一页面壳内以标签切换全球快讯、KOL和资讯源，每个标签只保留自己的首要任务。

### 渐进披露

- 卡片默认展示标题、状态、核心数值和简短说明。
- 因子解释、六周期证据、回测细节、模型消融、宏观背景和方法论使用 `details/summary`。
- 默认展开内容不得让用户在首屏看不到下一项主要任务。
- 展开控件必须有清晰文案、方向图标及键盘焦点状态。

## 8. 组件规范

### DisclosureCard

- 最小标题区高度约 `72px`。
- 内边距 `14px 16px`，圆角 `10px`。
- 标题区结构：眉题、标题、说明、核心指标、展开箭头。
- 指标使用等宽数字；说明为次级文字。
- Hover 仅改变表面明度，Active 使用轻微压暗，不做大幅位移。

### 市场脉冲

- 同时呈现基准标的、当日涨跌和四个预测周期。
- 每个周期占据等宽线段，颜色仅表达方向。
- 周期标签与方向必须同时存在，不能只靠颜色传达信息。

### 统计条

- 适合 3–4 个同级指标。
- 使用边界或表面变化分组；不要把每个数字都做成独立悬浮卡片。
- 标签为次级层级，数值使用衬线或等宽数字并成为视觉焦点。

### 筛选器与分段控件

- 最小高度 `40px`，移动端目标触控区域建议 `44px`。
- 筛选器必须允许换行；市场标签数量较多时使用横向滚动，不压缩文字。
- Active 状态使用背景、文字和边界共同表达，不能只改变颜色。
- 输入框使用略深于周围表面的填充，表示可输入区域。

### 数据列表与表格

- 标题和核心数据优先，日期、来源、状态其次。
- 大型表格放入可横向滚动容器，并设置合理的最小宽度。
- 移动端优先转换为可扫读卡片或保留明确滚动提示，禁止压缩成不可读的小字。
- 涨跌、费率、价格和百分比全部使用等宽数字。

### 状态

所有交互组件必须实现：Default、Hover、Active、Focus-visible、Disabled。

所有数据模块必须考虑：Loading、Empty、Error、Stale/Partial。状态应提供清晰文字，不只显示颜色或图标。

## 9. 动效

- 高频操作尽量不使用动画。
- Hover、展开箭头和按钮反馈控制在 `100–200ms`。
- 使用 `cubic-bezier(0.23, 1, 0.32, 1)` 作为主要缓出曲线。
- 只动画 `transform` 和 `opacity`；禁止 `transition: all`。
- 按钮按下可使用 `scale(0.97)`，不得小于 `0.95`。
- 必须遵守 `prefers-reduced-motion`，关闭非必要位移与连续动画。

## 10. 可访问性

- 所有交互元素可通过键盘访问，并有可见的 `:focus-visible`。
- 普通按钮最小高度 `40px`，关键移动端触控区域尽量达到 `44×44px`。
- 图标按钮必须提供 `aria-label`。
- 方向、状态和风险不能只依靠红绿颜色；必须附带文字。
- 表单必须有真实标签、明确的必填状态和可理解的错误提示。
- 弹窗需要语义角色、标题、关闭按钮及合理焦点行为。

## 11. 响应式规则

- 核心断点：`900px` 用于应用导航切换；`760px` 左右用于复杂双栏变单栏；`620px` 用于紧凑组件。
- 布局优先使用 Grid/Flex 的 `minmax(0, 1fr)`、换行和滚动容器，禁止用绝对定位逃避布局。
- 移动端必须保留核心结论，次级证据折叠；不能简单隐藏重要数据。
- 每次非平凡 UI 修改至少验证一个桌面视口和 `390×844` 移动视口。
- `document.documentElement.scrollWidth` 不得大于视口宽度，明确设计的局部横向滚动容器除外。

## 12. 工程约束

- 优先复用现有语义变量和组件；相同模式第二次出现时应抽为共享组件。
- Vue 组件使用原生语义和 `<script setup lang="ts">`，遵循项目导入与命名规范。
- 样式默认 scoped；真正跨页面的 token、焦点和排版基础放在 `src/assets/main.css`。
- 禁止在组件中复制一整套 Light/Dark 色值。
- 不引入新 UI 库来解决仅靠现有 CSS 和原生元素即可完成的问题。
- 图表颜色必须从当前主题 token 派生，并在主题切换后更新。

## 13. 交付检查

每次 UI 修改完成前必须执行：

1. `npm run type-check`
2. `npm run lint`
3. `npm run build`
4. `git diff --check`
5. 桌面端视觉检查
6. `390×844` 移动端视觉检查
7. 浏览器控制台错误与警告检查

同时完成以下人工检查：

- 模糊观察时，页面焦点和层级仍然清楚。
- 页面中只有一个首要视觉焦点。
- 所有颜色都承担语义或结构作用。
- 长内容可以展开、滚动或继续查看，没有靠缩小字号硬塞。
- Light/Dark、空数据、错误数据和较长中文/英文内容不会破坏布局。
- 用户能在十几秒内找到页面结论，并能继续核对原因和来源。

## 14. 当前已确认模式

- `AppSidebar`：桌面固定导航，移动端抽屉。
- `AppTopbar`：页面上下文、系统状态和主题切换。
- `IntelligenceView`：全球快讯、KOL监控和资讯源共用一个情报中心页面壳及标签导航；旧路由只负责重定向，侧栏不再为三个相邻任务重复占用入口。子页面嵌入时移除自己的重复大标题与外层留白，桌面和 `390×844` 均不得产生整页横向滚动。
- `DisclosureCard`：结论摘要与详细证据的渐进披露。
- `MarketHomeView` 市场脉冲：首页首要决策组件。
- `HotStocksPanel`：日榜/周榜切换，默认展示前8条并可展开Top 20。
- `CrossAssetView` 模型验证明细：默认收起回测、基线、消融与运行账本。
- `AssetTechnicalView`：传导链轮播位于走势图之前；页面使用“跨资产研究 / 分钟合约”双模式，不为合约决策另设重复侧栏入口。研究模式采用资产选择、主图、指标解释三栏结构；分钟合约模式依次展示交易所连接状态、合约与周期、真实 OHLCV 图、指标共振和交易判断。历史回测、进阶诊断和个人预警统一使用 `DisclosureCard` 按需展开；移动端摘要改为两列，只有回测明细表使用局部横向滚动。真实 OHLC 不可用时禁用 K 线并说明原因，不使用收盘价伪造蜡烛图。
- `ContractTradingWorkspace`：行情连接、图表和决策必须区分 Loading、Live、Reconnecting、Restricted 与 Error；禁止用示例数据冒充实时数据。K线图下先展示 `1m / 5m / 15m / 1h / 4h` 多周期矩阵与“盘口失衡 / 最优价差 / 主动买方占比 / 未平仓量变化”四项执行上下文，再渐进展开完整指标；周期和微观结构冲突必须把方向候选降级为等待。决策固定使用“做多候选、做空候选、等待确认、暂不交易、数据不足”五态，并展示指标一致度、ATR 预估区间、候选入场、止损、止盈、风险收益比和失效位。KDJ、单次盘口快照均只能作为趋势、动量、量价、资金费率等证据之一；未完成分钟级样本回测前必须标明规则合成边界。真实账户与下单不得在浏览器中处理，公开行情阶段无需 API Key。
- `AssetTechnicalView` 个人预警：规则创建和“已触发/观察中”解释放在紧凑指标栏；Viewer 不展示操作控件，Editor/Admin 操作同时接受服务端权限校验。触发状态使用文字与左侧边框共同表达，不只依赖颜色，每条规则都解释当前值、阈值或交叉条件。
- `AdminView` 技术指标配置：全局配置使用单一纵向管理卡片，先展示版本与常用模板，再按“启用指标、参数、权重、显示默认值、数据源”分组；版本账本默认折叠。桌面字段最多四列，窄屏依次降为两列和单列，不缩小表单文字硬塞内容。
- `FundResearchWorkbench`：美股基金和 A 股行业基金使用同一对比组件；基金选择器横向滚动且最多选四只，主图固定使用起点 100 的标准化走势，相关性图与 20/60/120 日摘要并列。完整方法论放在组件底部，不能把代理跟踪误差冒充官方指数跟踪误差。
- `FundResearchWorkbench` 传导背离：每只已选基金使用一行摘要展示状态、基金涨跌、宽基涨跌和相对差；前三条驱动及相关传导链放入默认折叠内容。确认、背离和证据不足必须同时使用文字与边界/颜色表达，且明确宽基代理关系和日期门槛。
- `QuantSignalsView` 期权卡片：估值/综合分/技术分作为顶层摘要；财报预期与历史事件窗口、LEAPS IV/IV Rank/Put-Call/期限结构分别放入两个有边界的证据区。无期权套餐或历史不足时保留完整结构并显示不可用原因，禁止使用示例值填充。
- 大型技术历史数据：使用单一数据加载模块按需获取可缓存的静态 JSON，资产技术页和量化信号页不得把完整历史序列重复打入页面 JavaScript；异步路由统一显示中英双语加载骨架，并遵守 `prefers-reduced-motion`。
- `DailyMarketPoster`：首页底部固定 `1200px` 社媒长图画布；页面使用局部横向滚动，导出使用 `2x` PNG，海报只展示每日决策所需的完整市场数据与最强五条传导链，不混入休眠规则库。
- 市场状态条：使用点状状态、文字和更新时间三重表达。

更新本文件时，应记录已经在真实页面验证的规则，不写尚未落地的视觉设想。
