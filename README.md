# 个人金融工作台

一个文字优先的个人金融研究入口，用来集中管理宏观、股票、加密资产、新闻与常用工具。

模块 更新频率
全球市场快讯 每15分钟
KOL监控 每6小时，约02:15、08:15、14:15、20:15
美股/A股热门股票 工作日18:20、次日06:30
美股市值前十与PE 跟随热门股票，工作日18:20、次日06:30
A股行业基金 每天18:30
美股基金与定投额度 每天09:15

GitHub Pages部署 main每次提交后；上述数据任务成功后也会自动部署

## 当前功能

- 按主题浏览 `src/data/webstack.yml` 中的全部网站资源
- 搜索站点名称、描述和域名
- 按分组筛选资源
- 使用浏览器本地存储收藏常用站点
- 比较中国市场的美股场内 ETF 与场外基金，可按规模和综合费率排序
- 跟踪美股与A股每日、每周热门股票 Top 20
- 每天自动更新场外基金的申购、定投状态和参考额度
- 监控A股行业与主题 ETF，按日、周、月、季度、半年、今年以来和近一年涨幅排序
- 在行情、热门股票和巨头估值模块展示最新价格，在基金模块同时展示场内价格和最新净值
- 每个自动数据模块展示最近更新时间与北京时间下次预计更新时间
- 对美股基金与A股行业 ETF 展示年运作费、购买手续费、佣金假设、溢折价和首年成本估算
- 跨平台监控 KOL 公开内容并自动识别内容中的股票提及
- 聚合全球市场新闻与央行、监管机构公告，按市场影响和发布时间筛选
- 跨资产驾驶舱统一监控股票、债券、外汇、商品和加密资产，并计算60日相关性矩阵与传导链
- 全球资产量化信号台按跨资产方向、价格动量和证据强度排列买入、持有、减仓候选
- 美股前十大期权候选使用可配置的 Forward PE 纪律线、20%缓冲和纳指中期环境，不把高估值自动解释为裸卖 Call
- 量化页面提供浏览器本地模拟信号账本；当前只跟踪标的价格，不模拟期权 IV、Theta 和成交滑点
- 管理员可运行 BTC 自动模拟交易：每5分钟评估一次，逐笔写入 D1，并汇总日/周/月胜率、盈亏比与净盈亏
- 通过统一情报中心切换全球快讯、KOL监控和常用市场信息源
- 响应式左右管理布局，支持浅色、深色模式与系统主题初始化

网站清单由 YAML 文件统一维护。界面不依赖站点 Logo 或内容图片，所有外部网站均在新标签页打开。

## 开发

```bash
npm install
npm run dev
```

开发服务器默认运行于 `http://localhost:2333`。

### Chrome PWA

Web 构建已包含 Web App Manifest 和 Service Worker。部署到 GitHub Pages 后，用 Chrome 打开站点，
可通过地址栏的安装图标或菜单中的“安装个人金融工作台”将其作为独立应用安装；已缓存的应用与静态数据
可离线打开，在线接口恢复后会优先读取最新数据。

### Electron 桌面应用

```bash
npm run dev:electron   # 启动 Vite 与 Electron 开发环境
npm run electron:dist # 为当前操作系统生成安装包到 release/
```

先将 `package.json` 版本号更新为发布版本，再推送同版本的 `v` 标签（例如 `v0.1.0`）。随后
`.github/workflows/release-electron.yml` 会在 Windows、
macOS 和 Linux 上分别构建安装包，并创建可直接下载的 GitHub Release。手动运行该工作流只会生成
Actions 构建产物，不会创建 Release。当前产物未做 Apple/Windows 商业代码签名，系统首次打开时可能
显示安全确认；正式分发可后续配置签名证书与公证密钥。

```bash

```

## 美股基金数据

基金清单位于 `src/data/us-funds.json`，覆盖纳斯达克 100 与标普 500 的主流境内 QDII
产品。运行以下命令可以手动刷新：

```bash
npm run update:funds
```

`.github/workflows/update-us-funds.yml` 每天北京时间 09:15 自动更新数据。额度采用天天基金销售
渠道展示值，并保留来源页面链接；实际可购买额度仍以基金公司公告和下单渠道为准。

## A股行业数据

行业榜数据位于 `src/data/a-share-sectors.json`。当前使用行业内规模最大的 ETF 作为代表，运行
以下命令可手动更新：

```bash
npm run update:a-share
```

`.github/workflows/update-a-share-sectors.yml` 每天北京时间 18:30 更新收盘数据。更新过程会同时
检查全部基金，任何一只抓取失败都不会覆盖上一版完整数据。

## 热门股票

运行 `npm run update:hot-stocks` 可刷新 `src/data/hot-stocks.json`：

- A股日榜按成交额排序，周榜按近5日涨跌幅绝对值排序；候选池取成交活跃的前200只股票。
- 美股日榜按 Nasdaq 成交量排序，周榜按最近5个交易日累计成交量排序，并排除 ETF、权证、优先股等非普通股。
- 两个市场均展示日榜与周榜前20名；抓取失败时保留上一版市场数据并标记为过期，避免空榜覆盖。

`.github/workflows/update-hot-stocks.yml` 在交易日自动刷新，榜单是市场关注度代理，不代表投资建议。

美股市值前十估值数据位于 `src/data/us-megacaps.json`，运行 `npm run update:us-megacaps`
可以手动刷新。股票范围与市值来自 Nasdaq，当前和市场预期 Forward PE 来自 StockAnalysis，
长期 PE 中枢为 CompaniesMarketCap 最近5个可用年度正 PE 的中位数。财报结果、下一季度和年度 EPS
共识、预期区间及近4周分析师上修/下修来自 Nasdaq；未正式公布的下一次财报日期显示“待公司公布”，
不会自行推算日期或用估算值填充。

## KOL监控

在 `src/data/kols.yml` 中增加名称和主页 URL，即可加入监控：

```yaml
- name: KOL名称
  url: https://平台主页地址
  enabled: true
  # feedUrl: https://可选的RSS或Atom地址
  # tags: [美股, 宏观]
```

运行 `npm run update:kols` 可手动解析；GitHub Actions 每6小时自动执行一次。YouTube 和标准
RSS/Atom 支持内容列表同步，普通网页支持公开元数据解析。小红书、微信和B站可能限制自动抓取，
此时页面会明确显示降级状态；配置可访问的 `feedUrl` 后可恢复完整内容同步。

## 管理员登录恢复

系统只保存访问口令的 SHA-256 哈希，无法找回已经使用或遗失的明文口令。如果所有管理员会话均已失效，
可在已经完成 Cloudflare 登录的本地项目中，为现有启用中的管理员生成一个短期一次性恢复口令：

```bash
npm run auth:recovery-code -- --email your-admin@example.com
```

默认有效期为15分钟，也可用 `--minutes 30` 设置5至60分钟的有效期。命令只向远端 D1 写入口令哈希和
审计记录，明文仅在本地终端成功结束时显示一次；登录成功后口令立即失效。不要把终端输出提交到 Git、
复制到 issue 或保存为 GitHub Secret。

## 免费准实时行情

首页、美股前十大和 A 股/美股热门股票会通过 Cloudflare Worker 的
`GET /api/market/quotes?symbols=...` 获取免费准实时快照。前端每60秒刷新一次，页面重新回到前台时立即
补刷；Worker 对单个标的缓存45秒，并且只接受当前项目行情池中的代码。API Key 不会发送给浏览器。

行情状态统一显示为“准实时 / 延迟行情 / 休市 / 行情过期”。接口或上游不可用时保留已发布的日线快照，
不会清空价格，也不会把日线数据标记成实时行情。当前上游为 Yahoo Finance chart 公共接口，属于免费
研究级来源，可能延迟、限流或调整；不得将其作为交易执行价格，公开再分发前需另行核对数据授权。

当前覆盖：首页主要股票指数、WTI、黄金、BTC、ETH，美股市值前十，以及每日/每周热门 A 股和美股。
场外基金仍按每日净值与定投额度更新，因为其不存在交易所盘中实时净值。

量化信号模块的深层接口位于 `src/utils/quant-signals.ts`。页面只传入跨资产数据、美股巨头估值和
策略配置，模块统一返回全球资产排名、期权候选、证据强度、风险闸门和方法限制。

当前期权规则使用35倍 Forward PE 纪律线和20%偏离缓冲，并优先评估365–730 DTE、Delta 0.60–0.80
的一至两年 LEAPS：估值、纳指中期方向和 EPS 修正共同偏多时给出 Long Call 或看涨价差研究模板；
高估值叠加市场及 EPS 修正偏弱时只给出看跌价差研究模板。进入财报前14天时自动降级为事件风险等待，
35倍以上不代表允许卖出裸 Call。所有候选在实时期权链、隐含波动率和流动性接入前都标记为不可执行。

长期期权市场数据使用 Massive 的
[Option Chain Snapshot](https://massive.com/docs/rest/options/snapshots/option-chain-snapshot)。启用步骤：

> 当前项目默认暂停实时期权市场数据接入，不会调用 Massive 期权接口，也不要求购买 Options 套餐。
> 已有 Forward PE、股票技术面、财报与方向研究继续工作；依赖真实期权链的数据明确显示为不可用。

如以后决定恢复：

1. 在 Massive 创建 API Key，并确认当前 Options 套餐能返回期权链快照、隐含波动率与持仓量字段。
2. 在 GitHub 仓库 `Settings → Secrets and variables → Actions` 新建 Repository secret，名称必须为
   `MASSIVE_API_KEY`。不要把密钥写入源码、README 或提交到 `.env`。
3. 在同一页面的 Repository variables 新建 `ENABLE_OPTION_MARKET`，值设为 `true`。未设置时工作流跳过
   期权步骤，避免误请求受限或付费接口。
4. 手动运行 `Update hot stocks` 工作流。量化页会分别显示最近尝试时间、最近成功取数时间和密钥配置状态。
5. 先确认至少一个标的显示“数据完整”或“部分数据”；LEAPS IV Rank 需要累计至少20个每日成功观测，
   因此初次接入不会立即生成 IV Rank。

官方当前列出 Options Basic 免费方案，但接口字段和套餐权限可能调整，应以 Massive 实际账户响应为准。
未配置密钥、返回401/403或无可用IV时，工作流只发出 warning 并保留旧成功数据，不会使用估算值填充。

量化页面优先连接 `web3-quant-api` Cloudflare Worker：服务端从仓库读取最新版跨资产与美股巨头数据，
生成统一快照并存入 D1；工作日北京时间18:45和次日07:45自动刷新。模拟信号账本按浏览器生成的匿名
客户端 ID 保存在 D1，仅记录信号时点的标的价格和后续价格变化。云端不可达时，页面会明确显示降级状态，
继续使用随构建发布的数据与浏览器 `localStorage`，不会阻塞阅读。

Cloudflare 相关代码位于 `worker/`，配置位于 `wrangler.jsonc`。本地初始化与验证使用
`npm run cloudflare:db:local`、`npm run cloudflare:check` 和 `npm run cloudflare:dev`；远端部署使用
`npm run cloudflare:deploy`。生产 API 为 `https://web3-quant-api.binson0426.workers.dev`，前端可通过
`VITE_QUANT_API_BASE` 覆盖。当前服务不保存真实券商密钥，也没有主网或真实资金下单适配器；可选的
Binance Testnet 凭据只能保存在 Cloudflare Secrets。

## 分钟合约工作台

“资产走势与技术信号”页面包含“跨资产研究 / 分钟合约”双模式，并默认进入分钟合约。该模式直接读取
Binance USDⓈ-M Futures 公开 REST 与 WebSocket 行情，通过 `/fapi/v1/exchangeInfo` 动态收录官方当前
处于 `TRADING + PERPETUAL` 状态的全部永续合约，不再维护固定币种白名单。标的可按代码搜索，并按加密
资产、股票合约、ETF、大宗商品、外汇、指数和其他分类筛选；官方目录不可达时，页面会明确切换为有限的常用
标的目录。备用目录包含已由 Binance 官方资料核对的 21 个股票合约、7 个 ETF 合约和 6 个商品合约；它只作
目录降级，不替代交易所实时交易状态。支持 `1m / 3m / 5m / 15m / 30m / 1h / 4h` 周期。公开行情阶段
不需要 API Key，也不读取余额、持仓或订单。股票与 ETF 标的同时展示公司/基金名称、底层市场和产品风险
标签，搜索支持合约代码、公司名称与交易市场。

交易判断合成 MA20/MA60、MACD、KDJ、RSI、ATR、相对成交量和资金费率，并使用固定的
`1m / 5m / 15m / 1h / 4h` 趋势矩阵、前20档盘口失衡、最优价差、最近20根K线主动买方占比及未平仓量
变化做二次确认。公开 WebSocket 同时更新当前K线与盘口，其他周期、资金费率和持仓上下文每60秒刷新；
多周期方向不一致、盘口与主动成交冲突或价差过宽时，方向候选会自动降级为等待。

页面固定输出做多候选、做空候选、等待确认、暂不交易、数据不足五种状态。候选入场、止损和止盈由当前
ATR 推导，尚未完成分钟级历史样本回测，不应作为自动下单依据。未连接、重连、地区受限和错误状态会明确
显示，禁止使用示例数据冒充实时行情。盘口失衡只是前20档的瞬时快照，不代表完整流动性，也不能单独作为方向信号。

模拟仓位模块使用当前标记价、名义仓位、杠杆、可编辑单边手续费率和资金费结算次数，计算保证金、往返
手续费、预计资金费、覆盖成本所需涨跌幅，以及同向交易计划的止损/止盈净损益。默认 `0.05%` 只作为可编辑
费率假设，不代表用户账户实际费率。交易前风险闸门根据模拟账户资金、可编辑单笔风险比例、止损距离、手续费
和不利资金费计算风险预算占用及建议名义仓位，并以“账户资金 × 杠杆”为上限；默认 `1%` 只是风险预算假设。
没有同向止损计划时不输出建议仓位。模拟不包含滑点、盘口冲击、维持保证金阶梯、强平费用和税费。

通过风险闸门的计划可写入独立的合约模拟交易账本。账本记录标的、方向、K线周期、入场/止损/止盈、
名义仓位、杠杆、成本假设、信号快照和风险预算，并按当前标记价估算方向收益率、净损益及保证金回报。
同一标的一次只允许一笔未关闭记录；切换回对应标的后可按最新标记价关闭并纳入胜率复盘。登录且具备
`paper.manage` 权限时，账本按用户同步至 Cloudflare D1，并在浏览器保留本地镜像；未登录或云端不可用时
自动写入本地账本，下次恢复云端连接时补传并以云端冲突记录为准。它与量化页面的股票期权模拟账本相互
独立，不连接 Binance 账户，也不代表真实成交结果。

当前“全部标的”特指 Binance USDⓈ-M 当前可交易的永续合约，不包含现货、COIN-M 交割合约或 Binance 的
其他产品线。股票与 ETF 标的是永续衍生品，不代表持有底层证券；需要额外关注基差、流动性、底层市场休市与
跳空风险，并以用户所在地区实际可用产品为准。

默认官方地址为 `https://fapi.binance.com` 和 `wss://fstream.binance.com/ws`。开发环境可使用
`VITE_BINANCE_FUTURES_REST_BASE` 与 `VITE_BINANCE_FUTURES_STREAM_BASE` 替换为经过授权的测试适配器；
不得用代理或中转规避 Binance 的地区资格限制。

API Key 只在 Testnet 订单验证时需要。密钥不得使用 `VITE_*` 变量、不得进入浏览器、源码、GitHub Pages
或日志。真实交易接入必须另行增加单独的受限密钥、固定 IP 白名单、禁用提现、独立账户、组合级风险上限、
熔断与人工总开关。当前版本没有任何主网或真实资金下单能力。

## BTC 自动模拟交易

管理员在“资产走势与技术信号 → 分钟合约”中可以管理 BTC 自动交易。Cloudflare Cron 每5分钟执行一次，
复用 `1m / 5m / 15m / 1h / 4h` 技术判断，并跟踪信号的新建、增强、减弱和证伪。默认只有方向明确、达到最低
方向分、证据置信度和连续确认次数，且不处于冷却期、日亏损熔断或连续亏损暂停时才开仓。管理员也可以
显式选择“无限制测试模式”，绕过这些入场门槛；该模式仍要求有效多空方向、止损/止盈和每方向持仓数量
上限，并且仍只允许 Paper 或 Binance Testnet。关闭风控不会自动提高胜率，必须通过影子结果和样本外表现
验证。默认最低方向分为 `|score| ≥ 55`，它与置信度分开：方向分描述多空强度，置信度描述
现有证据的一致程度。连续3笔亏损后默认暂停6小时。关闭“允许新开仓”只阻止新仓，已有仓位仍按止损、
止盈或信号证伪规则管理，管理员也可以执行一次带确认的紧急平仓。

核心方向分从 `btc-auto-v6` 开始加入 `regime-ensemble-v1` 市场状态策略组合。它同时计算时间序列动量、
Donchian式突破、均值回归和微观结构四组子策略：趋势状态提高动量与突破权重，震荡状态提高均值回归
权重，高波动状态提高突破与订单流权重。组合策略先以影子候选运行，达到晋级条件后才占最终方向分35%，
其余时间保持原有多指标基线，避免未经验证的升级影响开仓。突破窗口严格排除当前K线，避免用当前结果
反推突破阈值；策略升级生成新的确定性版本，使 v7 的交易与影子命中率不和旧版本混算。研究依据包括 AQR 的
[Time Series Momentum](https://www.aqr.com/Insights/Research/Journal-Article/Time-Series-Momentum) 与 NBER 的
[Volatility Managed Portfolios](https://www.nber.org/papers/w22208)；这些文献只支持研究方法，不构成本系统
能提高收益或胜率的证明。

为避免只观察融合后信号造成自证循环，系统会在每个周期同时保存原指标基线和状态组合候选的方向、分数、
市场状态与置信度，并在未来1小时用同源第一根完整K线回填两套结果。对比统计每个自然小时只取第一个
信号，且只有基线和候选在同一小时都给出方向时才组成配对样本，避免拿两个不同的择时集合直接比较胜率。
至少积累48个同小时配对方向样本后才给出结论。置信区间按“候选独赢/基线独赢”的配对分歧计算，而不是
把相关样本误当成相互独立。候选只有在方向命中率领先至少3个百分点、80%单侧置信下界仍高于0，并且
扣除往返手续费假设后的平均方向变化也高于基线时，才标记
为“明显占优”；否则显示结果混合或落后。只有“明显占优”会令下一周期采用35%候选权重；样本收集、
结果混合或落后均使用0%候选权重。每条信号同时记录实际应用权重，避免因为少量样本自动晋级且便于审计。
上述配对样本和晋级结论分别按趋势、震荡、高波动三种市场状态隔离；当前周期只读取当前状态自己的结论，
因此候选可以只在已证明有效的状态获得35%权重，不会把某一状态的优势外推到其他市场环境。
每种市场状态仅使用最近120组有效配对样本，新样本进入后最旧样本自动滚出，防止过时市场规律长期影响当前晋级判断。
信号模型版本与执行配置版本分开管理：修改持仓时间、冷却或风控参数仍会生成新的执行策略版本，但只要基线与候选模型算法没有变化，就继续在同一信号模型队列中积累配对样本。这些样本只用基线和候选的影子方向与未来结果，不会因为执行风控配置不同而混入实际下单结果。入场分数门槛研究同样使用该队列的原始基线分数，避免候选权重或执行配置改动造成样本断层。
候选晋级与入场分数研究采用 `btc-evidence-v4-consensus-gate` 证据口径：候选对比先筛选基线和组合模型在同一周期都明确给出方向的信号，再只取每小时最早一组；不会因为整点第一条是观望就丢弃后续有效配对，也不使用未来涨跌选择样本。未来1小时的方向变化还必须严格大于当前配置的估算往返手续费才计为一次命中。仅方向正确但不足以覆盖交易成本的小幅波动会计为未命中，避免高估可交易胜率。滑点和资金费仍需通过模拟盘或 Testnet 实际成交继续校准。
系统另外对每小时第一个基线方向机会做嵌套的“双模型同向”影子研究。只有基线样本和同向子集均至少30个、同向子集费用后命中率提升至少5个百分点、平均费用后变化更高，且保留至少30%的基线机会时，一致性过滤才会晋级。晋级后只阻止新开仓，不改变已有仓位的止损、止盈和反向信号平仓逻辑；关闭风控时仍遵循用户选择的无限制模式。

策略健康门槛默认检查最近20笔已平仓交易：Profit Factor 低于 `0.8` 或最大回撤达到 `3 USDT` 时暂停
24小时。暂停到期后允许一次探测交易；若该笔平仓后滚动样本仍不健康，会重新开始暂停，而不是永久锁死。
样本不足20笔时只展示积累进度，不据此阻止开仓。该门槛与单日亏损、连续亏损、平仓冷却分别计算，页面
会展示唯一首要拦截原因、滚动样本、Profit Factor、最大回撤和恢复时间。

每组会改变执行行为的配置会生成确定性的策略版本号，信号和逐笔交易都记录该版本。参数切换后连续确认
从1重新累计。没有任何当前版本交易时，系统最多允许一笔受控冷启动探测；该探测尚未平仓时，旧版健康
结论继续阻止增加新版本仓位。首笔平仓后，滚动健康度立即只使用当前版本样本；不足20笔时显示积累进度，
达到20笔后才执行 Profit Factor 与回撤门槛。页面会同时展示当前版本样本数和实际采用的风控样本范围。
分钟策略默认最大持仓60分钟，使真实交易窗口与1小时候选验证窗口一致；达到时间后按当期标记价平仓并记录
`timeStop`。该值可在配置中调整为0至1440分钟，0表示不启用时间止损。止损和止盈始终优先于时间退出。
系统还会对当前最低方向分与更严格的候选门槛（至少70分）做独立影子研究：每小时只取首个方向信号，比较
未来1小时命中率、扣除往返手续费后的平均方向变化与机会覆盖率。两组至少各有30个样本，且候选胜率提升
至少5个百分点、净变化更高、覆盖率不低于30%时才显示“严格门槛具备优势”。该结论只用于研究，不会自动
修改用户配置，也不会改变或重置正在积累的执行策略版本。
每个从本版本开始实际运行过的策略版本还会在 D1 固化一份执行参数快照，记录首次和最近使用时间；相同
版本只能更新时间，不能覆盖参数定义。CSV 会输出这些快照，使历史交易的版本哈希能够还原到当时的执行
参数。升级前已经存在且没有可靠参数证据的旧版本保持未知，不根据当前配置反推历史。
快照读取时会验证字段结构，并用参数重新计算策略指纹；JSON 合法但字段缺失、多出字段、类型错误或指纹与
版本号不一致时，快照会被隔离并记录警告。仪表盘最多返回最近50个版本以控制响应体，完整 CSV 则读取
全部有效策略版本，不因界面上限截断历史。

冷却期间连续确认会归零；冷却结束后必须重新积累确认，不能沿用平仓前的旧信号立即再次入场。每个5分钟
周期都会将方向、分数、置信度、演化状态、行情源和新开仓拦截原因写入 D1，保留90天。页面的“信号演化
审计”展示最近12条，用于验证规则是否被增强、减弱或证伪；该历史是研究与回测依据，不是收益承诺。

方向信号还会进行不下单的影子验证：用相同行情源在未来 `1h / 4h / 24h` 目标附近第一根完整 K 线回填
多空方向涨跌，并按当前策略版本显示样本数、命中率和平均方向变化。目标之后过晚的 K 线不会补填，避免
用事后更有利价格制造前视偏差。该结果不包含手续费、滑点、资金费和实际出入场规则，不能作为交易盈亏。
相邻5分钟信号高度重叠，样本数不代表独立交易次数。影子验证写入失败只记录警告，不得阻断活动仓位管理
或主策略周期。

默认执行模式为自动模拟盘。模拟盘优先读取 Binance Futures 公开行情；若官方接口因地区资格不可用，
只对模拟盘回退到 Coinbase Exchange 的公开 BTC-USD 现货 K 线，不使用代理规避限制。回退现货缺少资金费率、
盘口和期货基差，策略会因此保留更少的执行证据。每次开仓先把唯一订单意图写入 D1，再执行成交；网络结果
未知时保留待对账状态，明确拒绝时才回滚，防止定时任务重试产生重复订单。持仓模型支持按方向配置最多
1至20笔活动仓位；双向对冲开启后，多头和空头可以同时存在，反向信号不再自动平掉另一方向仓位，已有
仓位仍独立按照止损和止盈退出。

公开行情请求统一使用8秒超时，只对 `429`、`5xx`、网络故障和超时执行一次最多1.2秒的有界重试；下单请求绝不自动
重放。Coinbase 回退的四个周期改为顺序读取，避免在共享公共限额上制造请求突发。进入信号计算前还必须
确认最新完整 `1m` K线延迟不超过3分钟（Coinbase 回退因公共端缓存允许6分钟）、`5m` K线延迟不超过10分钟且标记价有效；超出范围时本周期报错并
停止判断，不使用“请求刚完成”冒充“行情仍新鲜”。

页面将定时器的上次尝试、上次成功、最近失败、连续失败次数、周期状态和下次五分钟计划时间分开显示。
只有完成行情读取、信号判断和审计写入才记为成功；关闭引擎且没有仓位时记为已跳过，不冒充成功，也不
清除历史连续失败证据。管理员紧急平仓只复用互斥锁，不改写 Cron 运行健康度。
面板打开期间每60秒静默读取一次最新状态，不触发策略周期或下单；页面从后台恢复可见时立即补一次同步。
静默刷新不会切换为加载占位，也不会与保存配置、立即评估或紧急平仓请求并发，组件卸载后会清理定时器。

逐笔记录包含执行模式、方向、数量、名义仓位、杠杆、成交价、止损/止盈、信号快照、平仓原因、手续费
假设和净盈亏。手续费率在开仓时固化，后续修改配置不会重算历史交易。退出判断按开仓后的完整1分钟 K 线
依次检查最高价和最低价；同一分钟同时触发止损与止盈时按止损优先，跳空止损使用更不利的开盘价，避免
用5分钟结束价美化模拟结果。页面按北京时间汇总今日、本周和本月的交易数、胜率、平均盈亏比、
Profit Factor、单笔期望、最大回撤与净盈亏，并展示活动仓位的估算未实现盈亏和止损风险。Paper 结果不包含
滑点、盘口冲击、资金费、强平、税费或真实账户佣金，不代表可实现收益。
页面同时绘制本月每日净盈亏、累计净盈亏和回撤曲线；交易日按北京时间归属，回撤按逐笔平仓路径计算，
而不是只比较每日收盘权益，因此当天先盈后亏或先亏后盈的风险路径不会被日汇总隐藏。
统计查询会从北京时间“本周开始”和“本月开始”两者中更早的时间读取，月初处于周中时仍包含上月属于
本周的交易；资金曲线则单独坚持从本月1日开始，避免周度补数污染月内曲线。
“逐笔交易与盈亏”支持导出 UTF-8 CSV，文件包含运行信息、日/周/月汇总以及后端返回的完整逐笔流水；
保留原始 ISO 时间、策略版本、费用、资金费和盈亏口径，便于在 Excel 或其他分析工具中独立复核。

如要验证官方 Binance Futures Testnet，先确认所在地和账户符合 Binance 条款，然后将密钥写入 Worker Secret：

```bash
npx wrangler secret put BINANCE_TESTNET_API_KEY
npx wrangler secret put BINANCE_TESTNET_API_SECRET
```

Testnet 模式最高允许5倍杠杆。启用双向对冲时，Worker 会核对并切换 Binance Futures 的 Hedge Mode，
开平仓订单分别携带 `positionSide=LONG/SHORT`；关闭时使用 One-way Mode。交易所不允许在已有不兼容仓位
时切换持仓模式，遇到这种情况周期会明确失败，不会静默改写仓位。
前端不会读取密钥，D1 也不保存明文。Testnet 平仓后先保留成交均价与手续费假设生成的估算结果；后续周期
通过账户成交明细与资金费收入记录核对真实已实现盈亏、USDT 佣金及持仓期间 BTCUSDT 账户资金费。资金费
接口不关联单笔订单，因此只按本系统仓位持有区间归属；Testnet 账户不应同时持有系统外 BTCUSDT 仓位。
多笔 Testnet 仓位持有区间重叠时，系统不会把账户级资金费重复归到每一笔交易，而会保留估算口径并明确
标记无法可靠归属。对账成功后覆盖为
“Testnet已对账”，失败则保留估算、展示待重试并按周期继续处理，不用缺失数据伪造精确结果。数据库升级和 Worker 发布使用 `npm run cloudflare:deploy`，该命令会先
应用远端 D1 migrations，再发布新的 Cron 配置；GitHub Pages 工作流只发布前端，不会替代 Worker 发布。

交易核心使用 Node 原生测试固化策略版本隔离、信号演化、入场门控优先级、滚动绩效暂停、保守止损/止盈、估算手续费、Testnet 对账计算和
北京时间日/周/月统计边界：

```bash
npm run test:trading
```

GitHub Pages 构建会先运行这组测试；任一风控不变量失败时停止部署。

## 全球市场快讯

运行 `npm run update:news` 可手动刷新 `src/data/market-news.json`。GitHub Actions 每15分钟聚合
GDELT、CNBC、华尔街日报、美联储、欧洲央行和美国证监会公开信息，自动去重、识别影响资产并分为紧急、高、中、低四级。
页面打开后每2分钟检查一次仓库中的最新版数据。定时任务可能因 GitHub Actions 排队而延迟，本模块不是
交易所级实时行情或完整新闻数据库。

英文标题通过可替换的翻译适配器生成中文译文，同时永久保留原文供核对。默认使用 MyMemory，已有译文会
按新闻 ID 缓存，只有新增标题需要调用翻译服务；可设置 `MYMEMORY_EMAIL` 提高公开 API 的使用配额。

## 跨资产市场驾驶舱
