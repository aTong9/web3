# 数据健康中心

入口 `/data-health`，侧栏「工具与资源 → 数据健康中心」。搜索数据集或点击状态汇总筛选，可以查看快照时间、记录数、快照后的预期更新时间、下一排程和来源异常，并导出 JSON 检查报告。

## 检查范围与口径

覆盖当前仓库的 19 份自动市场快照：跨资产、首页传导、资产技术信号、预测历史、基金传导、技术事件、A 股行业、境内美股基金、基金技术信号、热门股、美股大市值公司、美股技术信号、期权、核心资产研究及日线、市场新闻、KOL、Reddit、挪威主权基金。

- 「未超过预期更新」只表示时间及检查字段未触发异常，不证明行情值正确或服务实时在线。
- 「超过预期更新」表示此版本快照未包含按仓库排程预计的新快照；不直接判定 Actions 失败。排程采用北京时间，留有 10 分钟宽限；不自动识别交易所假期。
- 「来源需关注」保留快照中来源、市场、主要条目的 failed / partial / stale / unavailable 等状态；同一快照仍可有部分可用数据。
- 「缺失或不可用」包括缺少有效的数据时间、主要集合字段缺失或全部为空。
- 有 `dataUpdatedAt` 的数据优先使用该字段；为 null 时不使用 `attemptedAt` 或普通 `updatedAt` 冒充成功数据时间。期权数据的抓取尝试与可用数据严格分开。
- 记录数按每个数据集指定的主要集合计算，不是有效价格数量或全库记录总数；失败占位条目也可能计入，来源异常另外披露。

覆盖不含实时行情接口、Worker/D1、登录权限状态、人工资源目录、人工宏观日程、浏览器个人记录。它们需要各自的可用性或维护检查。

## 实现与维护

`src/utils/data-health.ts` 维护文件、路由、工作流与主要集合的映射。`scripts/data-health-plugin.ts` 在 Vite 加载/构建时读取快照，只向页面输出小型元数据；页面无需额外下载完整历史价格。生产数据来自构建时的快照，重新载入页面不会触发远端更新。

排程复用 `src/utils/data-schedule.ts`，新增 Reddit 每日 09:00，以及基金技术信号 09:15 / 18:30。后者由美股基金和 A 股行业工作流分别更新。修改 `.github/workflows/update-*.yml` 时同步核对排程和映射。

无法读取或解析的快照保留为异常条目，不静默从健康列表移除。Actions 链接供人工核对任务日志与部署状态；页面没有触发任务、写入或部署权限。

验证：`node --test tests/data-health.test.mjs`；浏览器已检查 19 条数据、状态与检索筛选、报告下载、390px 布局。首次构建该页 JS 约 14.3 kB（gzip 5.7 kB），包含元数据，不包含行情历史。
