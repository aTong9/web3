# 增收项目实践账本

入口：`/income-ledger`。项目目录中的「记录此项目的投入与到账」链接使用 `?project=<id>`，选中项目并筛选其记录；账本可返回对应项目资料。名称、工作方式与模式复用现有 `income-opportunities` 数据，平台规则仍以原资料的官方来源为准。

每条记录包含日期、项目、阶段、工时、币种、已到账收入、待到账收入、已付成本、备注与复盘结论。可新增、编辑、删除，按项目和日期范围（含首尾）筛选。自定义项目使用名称区分；同名自定义项目合并汇总，改名仅更改当前记录。旧目录项目即使下架，已保存名称和记录仍保留。

- 金额按币种分别汇总，不获取汇率、不把多币种相加。
- 到账净收益 = 已到账收入 − 已付成本。待到账不计入净收益，也不代表保证可收回。
- 有效时薪 = 到账净收益 ÷ 同币种工时；零工时显示「无工时，不计算」，不会产生无穷值。全体工时仅汇总当前筛选记录。
- 已到账填写实际入账金额；实际到账已经扣除的费用不可再次记为成本。跨币种收支拆分记录，工作时长只记录一次；不同币种时薪不适合直接比较。
- 待到账转为到账时编辑原记录，增加已到账、减少待到账，避免重复工时和收入。平台费、税费、退款等均由用户按实际情况手动记录，无费用预设。
- 工时允许 0–24，金额允许非负、最多 8 位小数，每项最多 10 亿；每个账本最多 5,000 条。金额由最短十进制表示转为 8 位小数整数单位后求和与相减，避免大额收支抵消时出现分币尾差。汇总最多显示 8 位小数；不替代正式会计与税务核算。

数据通过共享 `useLocalRecord` 存入 `market-desk-income-ledger-v1`，不上传账户或账本。账本根元素标记 `ph-no-capture`，按已安装 PostHog 的约定排除交互自动采集与会话回放。只有存储写入成功才替换屏幕中的已保存记录；写入失败或跨标签页冲突时保留草稿。存在未保存草稿时，离开页面、取消编辑、切换编辑对象均提示确认。浏览器刷新/关闭也有原生未保存提醒。

导出包含全部已保存记录（不受筛选影响、不包含草稿）。导入必须通过版本、字段类型、日期、金额、币种、长度与 ID 唯一性校验，并在确认后整体替换；格式错误不会覆盖已有账本。替换导入可能清空账本，操作前应导出备份。已有存储损坏时阻止写入并保留原值，用户需恢复存储或修复原备份后重新载入。

跨标签页冲突后重新载入会保留草稿。若同一条记录已经改变，再次保存前必须明确确认覆盖最新版本；取消则保留最新保存值和未保存草稿。已被其他标签页删除的记录不会被旧草稿自动恢复。

检查：`node --test tests/income-ledger.test.mjs`，覆盖格式与日期、币种隔离、未到账排除、零工时和仅成本、浮点小额、导入拒绝、删除写入失败及跨标签页冲突保护。
