## 本轮实现

- 资源页改为路由按需加载；原本首页会静态导入整份资源 YAML 和解析器。
- 资源页脚本、样式和书目从 PWA 预缓存移入现有运行时缓存；首次访问需联网，访问后才可能离线使用，缓存仍可能被浏览器淘汰。
- 检索支持多个空格分隔的关键词、全角字符、分类名；每个词都须匹配，可分别命中标题、描述、分类或 URL。分类内搜索仍受当前主题和分类限制。
- 收藏恢复时过滤非法值并去重；写入失败保留当前页面中的收藏，显示存储失败提示。
- 修复书目失败状态、重试、空结果及硬编码的 50 本计数；书目序号直接使用循环索引。
- 修复 `#MetKids` 被 YAML 注释吞掉的问题。新增校验覆盖全目录标题、URL 安全协议和重复条目。
- 新增 10 条官方资料入口，目录从 2,477 条增至 2,487 条，仍为 343 个分类。核对范围限本次新增条目及 MetKids，并未宣称存量链接均可用。

## 资料维护流程

1. 在现有分类中查找同一站点和用途，避免只为增加数量重复收录。
2. 打开原始官网或官方文档，核实用途及跳转目标；说明数据口径、访问条件，避免把资料入口称为已接入的数据服务。
3. 沿用 `title`、`logo`、`url`、`description` 字段。以 `#` 开头或其他可能被 YAML 解释的标题必须加引号。
4. 来源、日期、用途和限制写入 `docs/research/`，不把 URL 可访问当作数据准确性的证明。
5. 运行 `node --test tests/resource-navigation.test.mjs`；涉及代码再运行类型检查、lint、全量测试和构建。
6. 浏览器检查搜索、分类、收藏、移动端溢出与错误状态。

## 验证结果

- 初始类型检查与只读 lint 通过。
- 资源导航优化阶段新增检索、收藏解析与全目录数据校验，`npm test` 当时共 231 项通过。
- 资源导航优化阶段的生产构建：入口 JS 从 896.10 kB 降到 172.40 kB（未压缩）；gzip 从 274.21 kB 降到 65.36 kB。
- PWA 预缓存从 3317.68 KiB 降到 2090.52 KiB；此数字来自本地构建，不能代替真实网络加载时间。
- 资源页本身仍约 728 kB，构建保留大块提示；当前先隔离首页负担，未引入搜索服务或额外依赖。
- 最终类型检查、lint、构建与 `git diff --check` 通过。
- Chrome 桌面 1440px 与手机 390px 实测：多词/全角检索、收藏刷新恢复与筛选、存储失败提示、MetKids 名称排序均通过，无页面未捕获异常或横向溢出。
- 阻断书目请求后实测失败提示与重试恢复，验证无匹配书目的空状态。书目采用静态 JSON 按需 fetch，避免动态模块导入失败被浏览器缓存而无法重试。
- 生产预览实测：首页不请求资源页与书目文件；访问资源页和书目后断网刷新，两者均能从运行时缓存恢复。
